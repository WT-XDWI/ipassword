安全

随机，不靠运气。

真正的随机不是「看起来乱」，而是数学上无法预测。iPassword 的每一枚密码，都来自操作系统的密码学安全伪随机数生成器。

密码学级随机源

浏览器通过 crypto.getRandomValues() 直接向操作系统索取随机字节——在 macOS 与 iOS 上即由内核的 CSPRNG 提供。

它被设计用于密钥、令牌与会话 ID，因此同样适合用来生成你的密码。

拒绝采样，消除模偏置

把 32 位随机数直接取模会引入偏置，让某些字符出现得更频繁。我们用拒绝采样丢弃落在尾部的取值，让每个字符严格等概率。

除此之外，密码生成后还会经过 Fisher–Yates 洗牌，确保「必须包含的字符类型」不会固定在开头。

无模偏置 Fisher–Yates 洗牌 类型全覆盖

留在你的设备上

整个生成过程发生在浏览器本地。没有网络请求，没有遥测，没有第三方脚本，没有分析代码。

本站唯一的本地写入，是你勾选的那些偏好开关——密码本身从不落盘、不缓存、不进历史记录。

熵值，而不是感觉

强度由字符池大小与长度共同决定：熵 ≈ 长度 × log₂(字符池)。

默认的 20 位全字符池配置，已远超绝大多数服务对「强密码」的定义。

默认约 130 位熵 最大 64 位长度

不生成，也不存储

iPassword 不是密码管理器。它不保管你的密码，也没有找回功能——因为没有东西可被找回。

请把生成的密码交给可信的密码管理器，或者记在只有你能看到的地方。

技术规格

每一处细节，都经得起推敲。

下面是我们对随机性、性能与隐私的全部承诺。

密码长度
8 – 64 个字符，单字符步进可调，默认 20 位。
字符池
大写 A–Z、小写 a–z、数字 0–9、符号共 28 个，合计最多 90 个字符。
随机源
Web Crypto API — crypto.getRandomValues()，由操作系统 CSPRNG 提供，密码学安全。
偏置处理
拒绝采样（rejection sampling），消除取模偏置，字符严格等概率出现。
顺序处理
Fisher–Yates 原地洗牌，确保各字符类型位置随机。
熵值估算
按「长度 × log₂(字符池大小)」实时计算，展示在强度条右侧。
网络行为
零请求。页面不加载任何外部字体、脚本、图片或统计代码。
本地存储
仅在 localStorage 保存偏好设置（长度与开关状态），密码本身不写入任何存储。
剪贴板
使用 Clipboard API 拷贝；在非安全上下文中自动回退到 execCommand。
可访问性
支持键盘操作（回车 / 空格重新生成）、焦点可见样式，并适配 prefers-reduced-motion。
外观
自动跟随系统浅色 / 深色模式，支持动态字体与安全区域。
兼容性
Safari、Chrome、Edge、Firefox 的近期版本，桌面与移动端皆可。

常见问题

生成的密码会被发送到服务器吗？
不会。密码完全在浏览器内存中生成与显示，页面没有任何后端接口。你可以断开网络后刷新页面验证——一切照常工作。
为什么说它是「加密级」随机？
因为它调用的是 crypto.getRandomValues()，而不是 Math.random()。前者由操作系统的密码学安全伪随机数生成器驱动，输出不可预测；后者的输出序列可以被还原，绝不能用于密码。
密码长度选多少才够？
越长越安全，但也要看服务是否接受。一般来说 16 位以上就非常牢固；如果某个网站限制长度，用满它的上限即可。查看强度条右侧的熵值：超过 100 位熵就已经远超实际破解能力范围。
「排除易混淆字符」有什么用？
如果你需要手动把密码抄到另一台设备上，I l O S s Z z B b G g 这些字母很容易被看成 1 1 0 5 5 2 2 8 6 9。打开这个开关会把它们从字符池中移除，代价是字符池从 90 个降到 79 个（20 位密码的熵值从 130 降到 126，仍在「极强」区间）。

数字 0123456789 会完整保留，所以密码看起来依然正常。
我可以离线使用吗？
可以。把这一页保存为本地 HTML 文件，双击打开即可，功能和在线版本完全一致，且从此连一次网络请求都不会发生。
它会把我的密码保存在浏览器里吗？
不会。localStorage 里只记录你选择的长度和开关状态，方便下次打开时保持一致。密码一旦刷新页面就不复存在——请务必先拷贝再离开。
